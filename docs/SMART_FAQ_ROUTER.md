# Smart FAQ Intent Router

## Мета

Автовідповідь не повинна намагатися відповісти на кожне повідомлення, де
зустрілося знайоме слово. Правильний пріоритет: **false positive дорожчий за
мовчання**. Якщо готова відповідь не закриває питання повністю, повідомлення
залишається менеджеру.

Готові тексти FAQ не змінюються й нові відповіді не генеруються. Router лише
вирішує, чи доречно використати одну з уже існуючих відповідей.

## Pipeline

1. **Normalization** — регістр, пунктуація, UA/RU варіанти й допустима одна
   друкарська помилка для змістовних термінів.
2. **Candidate generation** — перевіряються всі FAQ rules, а не перший збіг.
3. **Evidence scoring** — конкретні слова/фрази мають більшу вагу за службові
   `як`, `де`, `хочу`; fuzzy має найменшу вагу.
4. **Question focus** — clause, де сформульоване питання, важить більше за
   побічний контекст після коми.
5. **Scope gate** — готова відповідь допускається лише до того виду питання,
   який вона реально покриває.
6. **Problem/exception gate** — помилки, персональні домовленості, торг,
   отримання/наявність промокоду не закриваються статичною довідкою.
7. **Transactional-data gate** — `Нова пошта, відділення 12`, `накладений
   платіж` без питання трактуються як дані для менеджера, а не FAQ.
8. **Multi-intent gate** — якщо в одному повідомленні два незалежні сильні
   наміри, одна часткова відповідь не надсилається.
9. **Conversation context** — FAQ не втручається, якщо менеджер уже відповідав
   у поточній розмові протягом 30 хвилин.
10. **Repeat suppression** — одна й та сама автоматична довідка не повторюється
    в support-thread протягом 6 годин: повторне питання переходить менеджеру.
11. **Attachment safety** — фото, документ, відео та voice ніколи не
    класифікуються лише за caption.
12. **Fallback** — при низькій впевненості router повертає `None`; працює
    існуючий flow передачі повідомлення менеджеру.

## Приклад зі production

`Як мені отримати промокод, я завжди замовляю тільки у вас?`

Старий matcher бачив `як + замов...` і через порядок rules вибирав `order`.
Новий router бачить, що основна тема — промокод, але наявна promo-відповідь
пояснює використання/акції, а не персональну видачу коду. Результат —
**автовідповіді немає, повідомлення лишається менеджеру**.

## Важливі інваріанти

- `RULES[].answer` не змінюються.
- Router не генерує текстів.
- Немає зовнішньої AI/LLM залежності, мережевих викликів чи нового ENV.
- Рішення детерміноване й тестоване.
- Для support context використовується вже існуюча історія БД.
- Для SQL останні support messages читаються окремим коротким DESC-query без
  розпакування старого cold archive.
