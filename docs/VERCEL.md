# Розгортання на Vercel

Один проєкт Vercel обслуговує три речі одразу:

| Адреса | Що це |
|---|---|
| `/` | панель керування для менеджера |
| `/app` | вітрина Telegram Mini App для покупця |
| `/api/*` | бекенд: API панелі, API вітрини, вебхук бота |

Усі троє мають жити на одному домені. Панель шукає бекенд за відносним шляхом,
а Telegram вимагає, щоб Mini App віддавався по HTTPS — і запити до API з нього
йдуть на те саме походження.

---

## Спершу прочитайте це

**Vercel — serverless.** Немає процесу, який живе між запитами. Звідси три
наслідки, які визначають усю конфігурацію:

- Бот працює через **вебхук**, а не polling. Немає кому тримати довге з'єднання.
- База має бути **Firestore**, а не Postgres. Пул з'єднань не переживає
  завершення функції, а Postgres швидко впирається в ліміт конектів.
- Стан багатокрокового діалогу потребує **Redis**. Без нього оформлення в чаті
  обривається посеред кроків — і не щоразу, а випадково, коли запит потрапляє
  в новий екземпляр функції.

Оформлення через Mini App Redis не потребує: там стан живе у вітрині, а не в
боті. Але текстовий шлях у чаті лишається, і без Redis він плаватиме.

---

## Крок 1. База — Firestore

Створіть проєкт Firebase і сервісний акаунт за [docs/FIREBASE.md](FIREBASE.md).

Потім **обов'язково** накотіть індекси:

```bash
npm install -g firebase-tools
firebase login
firebase use <ваш-проєкт>
firebase deploy --only firestore:indexes,firestore:rules
```

Firestore не має універсального індексу: кожна комбінація «фільтри плюс
сортування» вимагає власного. `firestore.indexes.json` містить 22 індекси,
виведені з коду `shop/repo/firestore.py` — по одному на кожен запит, який
робить бот, вітрина й панель.

Поки індекс не накочений, відповідний запит повертає `FAILED_PRECONDITION`, а
назовні це виглядає як 500 або порожній каталог у боті. У консолі Firebase
(Firestore → Indexes) індекси спершу мають статус *Building*; поки він не стане
*Enabled*, помилка триває.

> Якщо додаєте новий запит у `shop/repo/firestore.py`, одразу дописуйте індекс
> у цей файл. Створений вручну через посилання з логів у файл не потрапляє —
> і при розгортанні на новому проєкті все повториться.

## Крок 2. Redis

[Upstash](https://upstash.com) → Create Database, регіон ближче до `iad1`.

Скопіюйте **TCP-рядок** виду `rediss://default:<пароль>@<хост>:6379`.

Upstash показує ще й REST-URL (`https://...upstash.io`) — він для їхнього HTTP
API, бот його не зрозуміє.

Безкоштовного тарифу вистачає з великим запасом: стан оформлення це кілька
кілобайт на клієнта, які живуть хвилини.

---

## Крок 3. Деплой

Vercel → Add New Project → імпортуйте репозиторій.

**Framework Preset: Other. Root Directory: корінь репозиторію.**

Більше нічого в налаштуваннях збірки міняти не треба: `vercel.json` описує всі
три збірки (Python-функція, панель, вітрина) і маршрути між ними.

### Змінні оточення

| Змінна | Обов'язкова | Приклад |
|---|---|---|
| `BOT_TOKEN` | так | `1234567890:AA...` |
| `BOT_USERNAME` | так | `elfar_bot` |
| `JWT_SECRET` | так | `openssl rand -hex 32` |
| `DASHBOARD_PASSWORD` | так | довгий випадковий рядок |
| `FIREBASE_PROJECT` | так | `elfar-54b0c` |
| `GOOGLE_APPLICATION_CREDENTIALS_JSON` | так | вміст JSON сервісного акаунта |
| `DB_BACKEND` | так | `firestore` |
| `SERVERLESS` | так | `true` |
| `PUBLIC_URL` | так | `https://www.elfar.pp.ua` |
| `WEBHOOK_SECRET` | так | `openssl rand -hex 16` |
| `CRON_SECRET` | так | `openssl rand -hex 16` |
| `ADMIN_CHAT_ID` | так | `-1001234567890` |
| `ADMIN_IDS` | так | `123456789` |
| `REDIS_URL` | бажано | `rediss://...` |
| `CORS_ORIGINS` | ні | ваш домен |

**Без `BOT_USERNAME` не обійтися.** З нього будуються реферальні посилання й
кнопка переходу з групи в приватний чат. Без нього обидва тихо зникають.

**Ніколи не залишайте змінну створеною, але з порожнім значенням.** Для
`pydantic-settings` порожній рядок це не «не задано», а значення `''`, яке
треба розібрати в число. Конфіг це переживає — порожні значення відкидаються
й застосовуються дефолти, — але зрозуміліше просто видалити зайвий запис.

Решта параметрів магазину (назва, валюта, вік, реферальний відсоток, ліміт
бонусів, реквізити картки) **редагується з панелі**, у розділі «Налаштування».
Значення з оточення лишаються дефолтами: те, що не збережено в базі, береться
з них. Тому свіжий деплой працює без жодного запису в базу.

### Перевірка

```bash
curl https://<домен>/api/health
```

Дивіться поле `missing_env` — там список того, що ще не задано. Поки він не
порожній, увійти в панель не вийде. `DASHBOARD_PASSWORD` потрапляє в цей список,
поки дорівнює дефолтному `admin`: код навмисно вважає це «не задано», інакше
панель висіла б у мережі із загальновідомим паролем.

## Крок 4. Вебхук і кнопка магазину

```bash
curl "https://<домен>/api/telegram-setup?token=<CRON_SECRET>"
```

Один виклик робить дві речі: реєструє вебхук і ставить синю кнопку «Магазин»
біля поля вводу в чаті з ботом. У відповіді має бути:

```json
{"webhook_url": "...", "menu_button": "встановлено", "shop_url": "https://<домен>/app"}
```

Якщо `menu_button` каже «пропущено: потрібен https» — перевірте `PUBLIC_URL`.
Telegram приймає для Mini App лише HTTPS.

Викликайте після кожної зміни `PUBLIC_URL`.

## Крок 5. Планувальник розсилок

Вбудований cron Vercel на тарифі Hobby спрацьовує **раз на добу**. Для розсилок
цього замало: вони йдуть порціями, і між порціями потрібен зовнішній поштовх.

Заведіть завдання на [cron-job.org](https://cron-job.org):

```
URL:       https://<домен>/api/cron/broadcast-tick
Метод:     GET
Заголовок: Authorization: Bearer <CRON_SECRET>
Частота:   кожні 2 хвилини
```

Без цього розсилка назавжди зависне в статусі «Надсилається» — і кнопка
видалення для неї не з'явиться, бо видаляти розсилку в процесі відправки
заборонено.

---

## Крок 6. Наповнення каталогу

Зайдіть у панель на `https://<домен>/`, логін і пароль з `DASHBOARD_LOGIN` та
`DASHBOARD_PASSWORD`.

1. **Каталог → Категорії → Нова категорія.** Без категорії товар не додати.
2. **Каталог → Новий товар.**
3. **Налаштування** — назва магазину, валюта, реквізити, реферальний відсоток.

---

## Перевірка після розгортання

```bash
curl https://<домен>/api/health          # 200, missing_env порожній
curl -I https://<домен>/                 # 200, панель
curl -I https://<домен>/app              # 200, вітрина
curl https://<домен>/api/debug/routing   # routing_ok: true
```

Далі в Telegram:

1. `/start` — має прийти вітання з кнопкою «🛍 Відкрити магазин»
2. Кнопка відкриває вітрину → підтвердження віку → каталог
3. Додайте товар, оформіть тестове замовлення
4. **Замовлення має впасти в адмінський чат** з кнопками зміни статусу

Четвертий пункт найважливіший: він одразу перевіряє `ADMIN_CHAT_ID`, права бота
в групі й те, що сповіщення взагалі надсилається.

## Якщо щось не працює

| Симптом | Причина |
|---|---|
| `404: NOT_FOUND` на корені | маршрути в `vercel.json` не ведуть до зібраної панелі |
| 500 на всьому, зокрема `/api/health` | функція падає на старті — дивіться логи Vercel |
| 500 лише на каталозі та статистиці | не накочені індекси Firestore |
| Каталог у боті порожній, хоча товари є | те саме: бракує індексу під запит з фільтром `is_active` |
| Вітрина каже «не вдалося підтвердити» | відкрито не з Telegram, або невірний `BOT_TOKEN` |
| Кнопки магазину немає | не заданий `PUBLIC_URL`, або не викликали `telegram-setup` |
| Реферальні посилання порожні | не заданий `BOT_USERNAME` |
| Оформлення в чаті обривається | не заданий `REDIS_URL` |
| Розсилка висить у «Надсилається» | немає зовнішнього планувальника (крок 5) |
| Замовлення не приходить у групу | не заданий `ADMIN_CHAT_ID` або бот не доданий у групу |
| Бот мовчить у групі | так і має бути — див. нижче |

**Де дивитися логи.** Vercel → проєкт → Logs, фільтр по шляху. Трейсбек Python
видно повністю — там і буде справжня причина.

**Помилки Firestore про індекси** містять готове посилання
`console.firebase.google.com/...?create_composite=...`. Створити можна у два
кліки, але створене так не потрапляє у `firestore.indexes.json`. Правильніше
дописати індекс у файл і накотити через `firebase deploy`.

## Бот працює лише в особистому чаті

У групі чи каналі відповідь бачать усі присутні, а хендлери віддають приватні
дані: профіль показує бонусний рахунок і суму витрат, кошик — набір товарів,
історія — замовлення з адресою доставки. Тому все, що не приватний чат,
обривається до звернення до бази.

Виняток один — чат із `ADMIN_CHAT_ID`: там менеджери натискають кнопки статусів
і викликають `/stats`.

У групі бот відповідає лише коли його додали, написали `/start` або згадали
`@юзернейм` — надсилає привітання з кнопкою переходу в приватний чат. На решту
реплік мовчить.

## Чого на Vercel не буде

**Фото товарів.** Файлова система функції тимчасова. Або зберігайте
`image_file_id` з Telegram (бот показує фото за ним), або підключіть Cloudinary
чи Firebase Storage.

**Довгі розсилки одним махом.** Функція обмежена часом виконання, тому
відправка йде порціями з курсором. Це не обхідний шлях, а нормальна робота в
serverless — але вона потребує планувальника з кроку 5.
