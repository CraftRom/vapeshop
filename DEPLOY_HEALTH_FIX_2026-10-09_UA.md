# Виправлення помилкового відкату у фазі Nginx

Дата: 09.10.2026. API 1.18.1, вітрина 2.18.2.

## Причина

Наданий лог показує успішний startup API, роботу SalesDrive watchdog і старт Nginx. Помилка виникла у перевірці доступності після recreate Nginx.

У попередньому deploy.sh залишився `wget http://api:8000/api/health`. Він надсилав `Host: api:8000`, тоді як новий захист API дозволяє основний домен та loopback-адреси. У локальному тесті реальний API відтворив відповідь **400** для цього Host і **200** для `127.0.0.1`. Помилковий запит деплою спричиняв відкат справних сервісів. Сам наданий фрагмент не містить HTTP-статусу цього запиту; механізм підтверджено відтворенням у коді.

## Зміни

- Фаза Nginx тепер перевіряє `http://127.0.0.1:8080/__deploy_api_health` усередині контейнера Nginx. Цей наявний маршрут проксіює запит у API через runtime DNS із дозволеним `Host: 127.0.0.1`.
- Доступ до основного сайту перевіряється через **локальний HTTPS** із Host основного домену. Перевірка не переходить із HTTP на зовнішній домен через redirect і не залежить від зовнішнього DNS/Cloudflare.
- Старий `www.elfar.pp.ua` нормалізується на `elfar.pp.ua`, як у render-nginx та API.
- Для loopback HTTPS probe допускається тимчасовий self-signed сертифікат bootstrap. Це лише опція локального wget: налаштування TLS і перевірка сертифікатів користувацьких зʼєднань не змінені.
- Запити мають timeout 5 секунд. При остаточному збої скрипт додатково показує діагностику відповідного health-запиту.
- Відкат збережено для реальних збоїв. Host `api` не доданий до дозволених хостів.

## Як встановити

Розпакувати повний оновлений архів, зберігши кореневий `.env` і каталоги даних. Потім із кореня проєкту:

```bash
bash deploy/deploy.sh
```

Для цього виправлення не потрібні новий пароль, нові секрети, відновлення БД або видалення томів. Попереднє виправлення вимог до production-пароля включене в архів.

## Перевірки

- **5 тестів**: усі шість фаз реального deploy.sh із підміненим Docker, відсутність помилкового відкату, старий www-домен, відкат при недоступному внутрішньому маршруті та при недоступному HTTPS, відтворення відмови Host на реальному FastAPI.
- **19/19 перевірок справжнього Nginx 1.30.5**: конфігурація, loopback health із дозволеним Host, HTTPS основного домену, відсутність публічного JSON health на внутрішньому шляху, недовірені хости, промо, заголовки, медіа та rate limits.
- Перевірка порядку фаз деплою та синтаксису Bash/Python.

Логи: `qa/output/deploy-health-fix.log`, `qa/output/deploy-health-nginx.log`, `qa/output/deploy-health-phases.log`. Production-сервер із цього середовища не оновлювався; його стан після відкату потрібно перевірити на сервері.
