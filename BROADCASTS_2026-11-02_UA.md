# Створення та відправлення розсилок — 02.11.2026

Dashboard **1.77.0**, API **1.28.0**. Оновлення містить усі попередні зміни промокодів 1.76.0.

## Що змінено

- Список розсилок: картки з фото або позначкою тексту, пошук, фільтр статусів, пагінація по 20 записів, статистика доставки та журнал отримувачів.
- Нова форма з окремими блоками повідомлення, зображення, кнопки, аудиторії та розкладу. Попередній перегляд і доступні кнопки внизу; вміст форми прокручується окремо.
- Звичайний текст — початковий режим нових розсилок. Символи `<`, `>` і `&` більше не сприймаються як HTML. Для форматування є окремий режим HTML з серверною перевіркою тегів, посилань і вкладеності.
- Перевірка видимого тексту: до 4096 знаків без фото, до 1024 з фото. Фото та підпис надсилаються одним повідомленням; довгі підписи не обрізаються і не діляться без повідомлення користувача.
- Чернетки можна редагувати; інші розсилки можна дублювати. Щоб редагувати заплановану розсилку, спочатку зніміть її з черги.
- Форма зберігає ID після створення чернетки. Повтор після помилки запуску перевіряє поточний стан на сервері й використовує ту саму розсилку. Унікальний `client_key` захищає створення, якщо відповідь на перший запит втрачена.
- Попередня черга, журнал отримувачів, ліміти швидкості, відновлення після перезапуску й обережна обробка невідомого результату залишаються спільним шляхом доставки. Мережевий timeout не спричиняє прихованої повторної відправки.

## Зображення

Зображення можна завантажити файлом, перетягнути у поле, вставити з буфера, вибрати зі сховища або вказати прямим HTTP(S)-посиланням. Підтримуються JPG, PNG, WebP та GIF до 8 МБ. Перевіряються і розмір файлу, і його реальний вміст.

Локальні файли `/media/...` надсилаються Telegram через multipart/form-data, а не як відносне посилання чи file_id. Перед відправленням вони перетворюються на сумісне JPEG-фото; прозорість отримує білий фон, надмірні розміри зменшуються, для дуже вузьких фото додаються поля. GIF надсилається як статичне фото з першого кадру. EXIF-поворот враховується.

Пряме зовнішнє посилання завантажує сам Telegram. Воно має бути публічно доступним; для зовнішніх посилань рекомендовані JPG/PNG. Для WebP/GIF або сайтів, що блокують завантаження, використовуйте завантаження файлу.

Сховище має пошук по всіх файлах, сторінки по 24 зображення, повтор після помилки та вибір з клавіатури. Escape закриває верхнє вікно й повертає фокус у форму. Файли, що використовуються товарами або розсилками, не видаляються до прибирання посилань на них. Поки фото завантажується, збереження і запуск розсилки заблоковані.

## Встановлення

1. Збережіть резервну копію бази та чинних файлів розгортання.
2. Оновіть вихідні файли з архіву, зберігши власні `.env`, базу і каталог `/data`.
3. Виконайте `alembic upgrade head` у каталозі `backend` у середовищі застосунку або використайте чинний скрипт `deploy/deploy.sh`, що виконує міграції.
4. Перебудуйте та перезапустіть API, scheduler і dashboard. Новий API та виконавець розсилок мають працювати разом.

Нова міграція `fb4a8c2d1e70` після `fa3d7b2e1c90` додає `broadcasts.text_format`, `broadcasts.client_key` і унікальний індекс ключа створення. Чинні записи отримують `text_format=html`: старі HTML-розсилки та їхні лічильники не змінюються. Архів містить вихідний код і зібраний `dashboard/dist`.
